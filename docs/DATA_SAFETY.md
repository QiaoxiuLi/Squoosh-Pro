# Data Safety

The input contract is read-only. Squoosh Pro opens selected files for reading, inspects attributes, computes SHA-256, decodes pixels, and creates thumbnails. It never writes beside, renames, moves, deletes, or changes metadata on an input file.

Before encoding, the application captures path, file resource identifier, byte count, modification time, and SHA-256. The fingerprint is checked again before commit. A changed source fails with `sourceChanged`.

Outputs are placed in a local-time directory named `result_YYYYMMDD_HHmmss`; collisions add a numeric suffix. Existing files are never overwritten. The app writes a uniquely named hidden temporary file in the destination directory, calls `fsync`, checks signature, decodeability, dimensions, format, and target bytes, then uses a same-filesystem hard-link commit with no-overwrite semantics. Only the temporary file created by that operation may be removed after failure.

The application does not expose source overwrite or source deletion controls. A cancelled job keeps completed outputs and removes only its recorded uncommitted temporary file. Manifests, presets, and recovery records use atomic replacement in Application Support.

An unfinished job stores security-scoped bookmarks for each input and its output directory, plus fallback paths and source fingerprints, only in the app's Application Support container. Recovery requires an explicit History action. Resolved bookmarks start access only for the resumed job and stop access afterward. Completed recovery records are removed; jobs with failures remain available for retry.
